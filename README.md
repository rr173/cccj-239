# pairwise_dataset — 可订正的落盘成对比测稀疏矩阵

设施检测中，仪器对成对测点做有向比测 `(a, b, d, e)`（从 `a` 到 `b` 的精确整数
偏差 `d`、非负误差 `e`），可能从任意一侧先读。本数据集把结果落盘为稀疏矩阵，
分析员按任一测点的行/列都能取到同一份结果，而**盘上只保存规范方向的一份事实**
（排序位置小→大），反向读取在查询时折算为 `(-d, e)`，不存正反两份。

## 数据模型

- 测点：创建时给定稳定且互不相同的代码，排序位置为 `0..N-1` 稠密下标，
  `N ≤ 1e8`（坐标按 uint32 存储）。
- 事实：无序对 `{a,b}` 只有一份，键为规范方向 `(i,j), i≤j`；`a==b` 的自对
  只允许 `d=0`；缺测对不等于显式 `d=0`（前者不产生单元，后者是真实单元）。
- 证据：每条证据含**原始记录身份** `record_id` 与**有效批次** `batch`，
  以及原始方向与原值 `(src, dst, raw_d, raw_e)`。一个事实可挂多条证据，
  只在折算值相同的条件下合并；冲突不会被后面的行盖掉，而是拒绝发布。

## 首装与订正（事务）

首装与订正走同一条事务路径：

```python
from pairwise_dataset import Dataset

ds = Dataset.create("/data/ds", stations=["A", "B", "C", "D"])
with ds.correction() as tx:                 # 首装 = 空版本上的第一个订正事务
    tx.add("rec-1", "batch-1", "A", "B", 5, 0.5)
    tx.add("rec-2", "batch-1", "B", "A", -5, 0.5)   # 折算值相同 -> 合并证据
    tx.commit()

with ds.correction() as tx:                 # 订正：同一事务内撤旧增新
    tx.add("rec-9", "batch-2", "A", "B", 7, 0.5)    # 与 rec-1/2 临时不一致，允许
    tx.revoke("rec-1")
    tx.revoke("rec-2")                                # 撤回必须引用已存在的记录
    tx.commit()        # 提交时校验：每个受影响测点对的剩余支持相互一致才发布
ds.close()
```

- 撤回引用不存在的记录 → `UnknownRecordError`；记录身份重复 →
  `DuplicateRecordError`；最终剩余证据折算值不一致 → `ConflictError`，
  整个事务不发布，数据集保持原版本。
- 证据撤空的测点对不再生成单元。

## 版本与并发（MVCC）

每次提交生成新的不可变版本目录并原子切换 `CURRENT`（写文件 → fsync →
`CURRENT.tmp` → `os.replace`）。读事务钉住开始时的版本：

```python
snap = ds.read()          # 钉住当前版本；与写者并行也不会在同一矩形读出新旧混搭
res = snap.window(r0, r1, c0, c1)
snap.close()
```

盘上只保留**当前版本**与**被读事务钉住的版本**，其余由 `gc()`（提交后自动
触发，也可手动调用）清理；不支持任意回看历史版本。

## 矩形窗口读取

`window(r0, r1, c0, c1)` 以排序位置给两个半开区间，交付其中有向单元，
按 `(row, col)` 排序：

- 正向命中：规范点 `i∈[r0,r1), j∈[c0,c1)`（含对角，标记 `self`，只一条）；
- 反向命中：规范点 `i∈[c0,c1), j∈[r0,r1)` 且 `i<j`，折算为 `(j, i, -d, e)`，
  标记 `reverse`，**指向同一批支持证据**；
- 窗口完全扫过对角线时，两个真实朝向各一条、对角单元一条；
- 完全没有证据的测点对不生成单元；
- `res.evidence_index` 为窗内证据索引（`record_id -> EvidenceRef`）；
- `res.stats["nodes_visited"]` 暴露本次查询的索引节点访问数。

另有 `snap.pair(row, col)` 按任一测点的行/列取同一对结果（无证据返回 `None`）。

## 补采工单（批次缺口分页）

调度员从打开的读快照建立工单，给出本次检测的覆盖要求，就能查到仍需补采的
测点对。每条要求为 `(a0, a1, b0, b1, k)`：从两个不相交（可重叠）的非空半开
区间各取一个测点组成的无序对，至少要有 `k` 个不同的有效批次。一份工单至多
128 条要求。

```python
with ds.read() as snap:
    order = snap.backfill([
        (0, 8, 8, 16, 2),      # 左半 x 右半，至少 2 个独立批次
        (4, 12, 14, 20, 3),    # 与上一条重叠，门槛取最大值而非相加
        (8, 16, 0, 8, 2),      # 镜像写法：覆盖同一批对，不重复派单
    ])
    order.version_seq          # 工单冻结的版本
    order.total_gaps           # 精确缺口总数（可以是几十亿）
    page = order.page(0, 100)  # 从缺口序号 0 起取 100 条（页长 1..1000）
    page.next_index            # 下一页的起始序号
    page.entries               # 每条含 row/col、required_batches、existing_batches
    order.page(order.total_gaps, 100).entries   # 越界 -> 空页
```

- 两段没有先后；两段允许重叠，但自对 `{i,i}` 不是待检对。两段完全相同时
  要求覆盖段内所有 `i<j`。
- 一对命中多条要求时取其中最大的批次门槛，**不叠加**；不受任何要求约束的
  对不进入工单。
- 批次从现有比测证据里取：同一测点对同批的多条证据只算一次，不区分原始方向；
  没有证据即零批。已有读数 `d/e` 的大小不影响是否达标。
- 缺口按 `(row, col)` 字典序、以较小位置在前排列；序号从零起，最后一页可
  不足页长；`index >= total_gaps` 返回空页。非法区间、门槛或分页参数报
  `ValidationError`。
- 建单后规则、快照版本与准备结果一并冻结：后续订正不能移动旧工单的页边界；
  用订正后的新快照建单则按新证据判断。快照关闭后取页报 `DatasetError`。
- 宽范围要求隐含的应测对可达数十亿。建单只处理规则端点压缩出的“段对”和
  快照中实际保存的事实（计算与临时空间不随隐含对数增长）；分页用顺序统计
  直接定位，不为跳页遍历前面的缺口，并复用建单的准备结果。已有的比测写入
  与窗口读取接口不受影响。

## 追补（增量同步）

下游台账按原始记录 ID 保存比测证据、只记住上次同步到的版本号时，可以在
打开的目标读快照上交入该游标，一次拿到追平所需的**净变更**和下次游标：

```python
with ds.read() as snap:
    res = snap.catchup(ledger_cursor)      # 台账上次同步到的版本号
    for ch in res.changes:                 # 按记录 ID 字符串序的净变更
        if ch.new is None:
            ledger.pop(ch.record_id, None)          # 目标端已不存在
        else:
            ledger[ch.record_id] = ch.new           # 新增或内容被替换
    ledger_cursor = res.to_seq             # 保存为下次游标
```

- 比较的是两端的**证据表**（`EvidenceRef`：批次、原始方向的两个测点
  位置、原始偏差与误差），不是折算后的矩阵读数，也不是逐轮操作流水：
  跨轮撤回再用同一 ID，即便折算后读数没变，只要原始证据不同就交付；
  误差按数值比较。`old`/`new` 各为一端内容，不存在的一端为 `None`。
- 净变更：每个有差异的 ID 只出现一次；中途出现又消失的 ID、最终恢复
  为起点同样内容的 ID 都不交付。把变更应用到起点台账后，记录及内容
  与目标快照一致。
- 每个快照支持从它往前最多 **16** 次成功订正的追补（含恰好 16 次）；
  成功但未改动证据的订正也占一轮。从快照自身追补得到空差异。
- 追补起点：新建数据集从它的初始版本开始；已有数据目录第一次用本版
  打开时从当时的当前版本开始（允许这一次性读取已有证据建立起点），
  以后重开不重置。起点之前、超过保留范围、比目标更新或非法的游标，
  以及已关闭的快照，都报错，不给出部分差异。
- 旧快照仍开着时，用它追补的范围和结果不因新提交而变；它关闭后，不再
  被当前版本或其他活动快照需要的追补历史由 `gc()` 回收。追补历史是
  独立的增量文件，**不为追补延期保留完整的历史矩阵目录**。
- 一轮订正对矩阵和追补记录同时生效：被拒绝或在切换 `CURRENT` 前中断
  的订正不会在重开后出现在追补里；已发布的订正重开后仍可追补。
- 成本：提交侧只写本轮增撤（不整仓比对）；一次追补只重放所请求跨度内
  发生过变化的记录与相关索引（`res.stats["records_touched"]`），不遍历
  未变的证据。

## 索引与性能

规范点集上建平衡 k-d 树（交替按行/列切分），一次建树同时服务正、反两次
矩形查询；窗口读取不随窗口面积或全仓事实数线性扫描。实测（见测试）：

- 20 万事实中构造 10 万条"单轴命中但不在目标矩形"的记录，空矩形查询仅访问
  2138 个节点（单轴扫描需 ≥5 万）；
- 15 万条不相交记录上 8×8 热点窄窗，最坏访问 48 个节点。

## 盘上布局

```
<root>/
  stations.txt            # 测点代码，行号 = 排序位置
  CURRENT                 # 当前版本目录名（原子切换）
  versions/
    v_00000001/
      meta.json           # 版本号、事实数、证据数
      I.bin J.bin         # 规范点坐标（按 (i,j) 排序），uint32
      D.bin E.bin         # 折算值 int64 / float64
      ev_off.bin          # 每事实的证据区间偏移
      ev_rec/ev_batch/ev_dir/ev_rd/ev_re.bin
      records.json        # 记录身份表
      batches.json        # 批次表
  changelog/
    meta.json             # 追补起点（anchor，重开不重置）
    c_00000002.json       # 一轮成功订正的证据增撤（adds/removes 原始内容）
```

## 限制（本范围有意不泛化）

- 仅二维矩阵，不泛化到其他张量形式；
- 单进程、单写者；同一目录同时只打开一个 `Dataset` 实例；
- 误差 `e` 以 float64 存储，合并一致性按精确位值判定；
- 每个版本为全量快照（提交开销与事实总数成正比），版本间不共享段；
- 追补保留窗口固定为 16 轮成功订正，更早的净变更需由台账重新全量同步。
